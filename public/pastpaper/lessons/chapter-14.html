14 通信与互联网技术 Communication and internet technologies

中文知识点提要 · Cambridge 9618 · 2027–2029 考纲

14.1 Protocols

练习本知识点 →

Protocol 定义通信的格式、顺序、解释和错误处理规则，使不同设备能互操作。分层提供清晰接口、便于替换实现与定位问题；发送时 encapsulation 逐层添加控制信息，接收时反向解封装。

TCP/IP 层主要职责相关例子
Application应用消息与服务规则HTTP、FTP、SMTP、POP3、IMAP、BitTorrent
Transport端到端进程通信、端口；TCP 还提供排序/重传等可靠传输TCP、UDP
Internet逻辑寻址及跨网路由IP，router
Link本地链路帧、MAC 寻址与介质传输Ethernet、Wi-Fi

路径例：浏览器 HTTP 消息 → TCP 分段/端口 → IP 源目的地址 → 本地链路 frame；路由器逐跳选择下一网络并更新链路封装；接收主机逐层重组、交付应用。

协议用途与区别
HTTP请求/传输网页及其他 Web 资源；HTTPS 为 HTTP 加 TLS 保护
FTP文件传输；不要把原始 FTP 当成默认加密协议
SMTP邮件客户端提交及服务器之间发送/转送邮件
POP3从服务器获取邮件，典型用途为下载到本地；可配置保留服务器副本
IMAP在服务器管理邮箱状态，多设备同步
BitTorrentP2P 分块共享，不同 peer 可同时下载与上传块

TCP 的确认、序号、重传与流量控制有开销；UDP 本身不提供这些可靠性保证，适用于能容忍丢包或由应用处理的场景。不要断言实时数据永远只用 UDP。

14.2 Circuit switching and packet switching

练习本知识点 →

Circuit switching 先建立专用路径/保留资源，通信中持续占用，结束后释放。建立后延迟和带宽可较稳定；空闲时资源浪费、建立需要时间，适合持续传输需求。

Packet switching 将消息拆成带头部的数据包，网络链路共享。数据包可能经不同路径、乱序或丢失；接收端按相应协议重组，必要时重传。带宽利用率高、可绕故障，但有头部开销、排队延迟/jitter，不能保证每包按同一路线到达。

Router 读取目的 IP，查路由表，选择下一跳并转发；“最短”不是必然按地理距离，取决于路由 metric。端到端完整性/重组不应全部归给路由器。

3. 按四层逐一说清“应用消息、端口、IP、MAC”处理的对象。
