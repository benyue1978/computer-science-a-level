06 安全、隐私与数据完整性 Security, privacy and data integrity

中文知识点提要 · Cambridge 9618 · 2027–2029 考纲

6.1 Data Security

练习本知识点 →

Security 是防止未经授权的访问、修改、破坏与丢失；privacy 关注个人信息的收集、使用和披露是否符合授权与合理预期；integrity 是数据准确、完整、一致的状态。获准读数据不代表获准向他人披露。

威胁原理/风险对应措施及局限
Virus依附文件/程序传播，执行时感染或破坏更新反病毒软件、补丁、限制执行；新病毒可能漏检
Spyware暗中收集行为、账户等信息反间谍软件、可信安装来源、权限控制
Unauthorised access/hacker利用漏洞或被盗凭证访问系统强认证、最小权限、更新、日志监测
Phishing伪装可信消息/网站诱骗用户交出信息培训、检查域名、独立渠道核实、MFA
Pharming篡改 DNS/解析或相关配置，重定向到假站保护 DNS/设备配置，核验证书、及时更新
  • Accounts/access rights：每人使用可追责账户，按职责授予所需权限。
  • Password + MFA：结合不同认证因素；生物识别方便但可能误识别，泄漏后难以更换。
  • Firewall 根据规则过滤连接/流量，不保证阻止所有恶意附件或获准通道内的攻击。
  • Anti-virus/anti-spyware 检测隔离威胁，需要更新。
  • Encryption 把可读明文变成密文，保护存储/传输机密性；密钥泄漏会失去保护。
  • Digital signature 用于验证来源及检测篡改，不能单独保密消息（详见第 17 章）。
  • 物理保护、定期离线/独立备份、恢复演练可减轻盗窃、故障和破坏损失。

6.2 Data Integrity

练习本知识点 →

Validation 检查是否符合规则；不保证事实正确。Verification 检查输入/传输与来源是否一致，也不保证来源本身正确。

Validation例子
Range check分数在 0–100
Limit check数量不超过库存上限
Format check代码符合两字母加四数字的模式
Length check学号恰好六字符
Presence check必填字段不为空
Existence check输入的商品编号已存在于商品表
Check digit由其他数位计算附加位，重新计算并比较

Verification：visual check 人工与原件比对；double entry 两次独立输入后比较，仍可能两次犯同一错误。

传输检错

  • Parity bit：令一个数据单位中的 1 的数量为指定奇/偶。偶校验例：数据 1011001 有四个 1，附加 0；收到的总数变成奇数就说明错误。能检测任意奇数个位翻转，但偶数个位翻转可能漏检。
  • Block parity：数据按行列排列，分别设置校验位；单个位错误可通过错误行与列交点定位，但不能保证定位所有多位错误。
  • Checksum：发送者按规定算法计算校验值一起发送，接收方重算比较；不匹配要求重传。不同错误可能产生相同 checksum，它不是密码学认证。
  • Check digit（数据编码中的附加数位）、parity（位数约束）、checksum（数据块的计算结果）不要混用。

自测与易错点

1. 错把年龄 21 输入为 22，为什么范围校验可能通过？如何增加核对？

2. 为偶校验数据 1100101 加校验位（答：0），解释翻转两位为何可能不被发现。

3. 场景题按“威胁 → 如何发生 → 措施 → 为什么有效”回答，不能用 encryption 回答所有安全问题。
