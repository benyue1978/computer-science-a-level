13 进阶数据表示 Data Representation

中文知识点提要 · Cambridge 9618 · 2027–2029 考纲

13.1 User-defined data types

练习本知识点 →

自定义类型用业务含义约束数据，提高可读性、复用性和一致性。

TYPE Day = (Mon, Tue, Wed, Thu, Fri, Sat, Sun)
TYPE IntPointer = ^INTEGER
TYPE StudentRecord
    DECLARE ID : STRING
    DECLARE Mark : INTEGER
ENDTYPE
TYPE LetterSet = SET OF CHAR

Enumerated type 是有限命名值集合；pointer 保存某数据位置的引用，需理解空指针及解引用。Set 是无重复元素集合，支持成员测试及集合运算；record 是命名字段组合；class 定义属性与方法，object 是其实例。非复合与复合分类按考纲：枚举/指针为 non-composite，set/record/class-object 为 composite。

13.2 File organisation and access

练习本知识点 →

文件组织 organisation存储方式适用场景/访问
Serial按到达顺序保存，无须按键排序日志、批量追加；通常顺序读
Sequential按 key 排序按键顺序批处理；可顺序访问，有索引/地址支持时也可直接访问
Random通过 record key 与地址映射定位频繁按键读写，需处理冲突和空槽

Organisation 是存放安排；access 是如何查找/读取。Direct access 指定位目标而不必从头逐条读取，不等于“数据随意排列”。

Hash function 将 key 映射到槽/地址，如 h(key)=key MOD 10。21 和 31 都映射 1，形成 collision。Linear probing 检查下一槽并在尾部回绕；chaining 用链保存同槽项目。读与写必须使用同样的 hash 和冲突策略。删除开放寻址项目通常需要 deleted 标记，直接当作从未用过的空槽可能截断后续查找。

13.3 Floating-point numbers

练习本知识点 →

本考纲使用补码 mantissa 与补码 exponent，必须按题目位数/二进制小数点位置解读，不能默认 IEEE 754 格式。

value = mantissa × 2^exponent。若尾数有 m bits，二进制点在符号位之后，则位权为 −1, 1/2, 1/4, …。e-bit 指数补码范围是 −2^(e−1) 到 2^(e−1)−1。

转换例（8-bit mantissa，4-bit exponent）

  • 01010000 0011：尾数 0.1010000₂ = 0.625，指数 +3，值为 5。
  • 10110000 0011：尾数 −1+1/4+1/8 = −0.625，指数 +3，值为 −5。
  • 十进制 6.5：110.1₂ = 0.1101₂ × 2³ → 01101000 0011。

Normalisation 规格化

非零补码尾数通常使最前两位不同：正数 01…，负数 10…。这样尽量使用有效位，增加精度，并在固定格式下提供规范表示。

例：00101000 0100 表示 0.3125×16=5；尾数左移一位成 01010000，指数减少 1 成 0011，数值不变。移动时必须保持符号、检查边界，零通常作为特殊情况。

范围与精度

固定总位数下，更多尾数位提高 precision；更多指数位扩大 range。很多十进制小数（如 0.1）在二进制中无限循环，有限位会舍入/截断；重复计算可能累积误差。Overflow 为结果大到超出可表示范围；underflow 为非零结果太接近零，无法以该格式正常表示。不能把 underflow 解释成“所有负数太小”。

自测与易错点

1. 01100000 0010 的值？答：0.75×4=3。

2. 解释为何增加指数位不能直接改善小数有效精度。

3. 对随机文件演示 21、31、41 依次插入以及查找 41 的完整 probing 路径。
