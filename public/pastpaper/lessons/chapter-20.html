20.1 Programming Paradigms

练习本知识点 →

Paradigm 是组织计算的思考方式。P3 涵盖本章全部范式；P4 不考 low-level 与 declarative programming，但考程序实现及测试证据。

Low-level 与 imperative

Low-level 接近硬件，通过机器/汇编指令控制寄存器与内存；需要能用 immediate、direct、indirect、indexed、relative 寻址写/追踪代码，详见第 4 章。

Imperative/procedural 以改变状态的语句、选择、循环和子程序组织求解，承接 AS 第 11 章。设计时区分输入、处理、输出及参数接口。

Object-oriented programming（OOP）

术语含义
Class / object / instance类是属性与方法的定义；对象是类的实例
Attribute/property对象保存的状态
Method操作对象状态的行为
Encapsulation将数据与方法结合，控制外部直接访问
Getter / setter受控读取/修改属性，可执行验证
Inheritance子类继承并扩展父类特征，表示 is-a
Polymorphism相同接口/方法调用在不同类型对象上表现不同
Containment/aggregation一个对象包含/引用其他对象，表示 has-a
class Account:
    def __init__(self, owner, balance=0):
        if balance < 0:
            raise ValueError("Negative opening balance")
        self.__owner = owner
        self.__balance = balance

    def get_balance(self):
        return self.__balance

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("Amount must be positive")
        self.__balance += amount

    def description(self):
        return "Standard account"


class SavingsAccount(Account):
    def __init__(self, owner, rate):
        super().__init__(owner)
        self.__rate = 0
        self.set_rate(rate)

    def set_rate(self, rate):
        if not 0 <= rate <= 1:
            raise ValueError("Rate must be between 0 and 1")
        self.__rate = rate

    def description(self):
        return "Savings account"


class Customer:
    def __init__(self, name, account):
        self.name = name
        self.account = account  # has-a / aggregation：引用已有对象

SavingsAccount 是 Account；Customer 有一个 Account。将两种账户放在同一集合，对每个对象调用 description 可得到不同结果，是 overriding 支持的多态示例。Python 双下划线使用 name mangling，不是不可绕过的安全边界；考试表达关注受控访问原则。真实金额通常避免二进制浮点误差，可用最小货币单位整数或十进制定点表示。

Declarative programming

声明事实、规则和目标，由推理机制找满足条件的解，而非逐条写求解步骤。以下为 Prolog 风格说明，具体语法按题目：

parent(anna, ben).
parent(ben, cara).
grandparent(X, Z) :- parent(X, Y), parent(Y, Z).

目标 grandparent(anna, Who).：匹配规则，先以 X=anna 找 Y=ben，再找 Z=cara，因此 Who=cara。变量经 unification 统一；失败时可 backtrack 尝试其他事实。事实表达已知关系，规则表达推导，goal 是查询。不能将 parent(X,Y) 的参数方向随意颠倒。

20.2 File Processing and Exception Handling

练习本知识点 →

READ 读已有文件；WRITE 创建/覆盖；APPEND 末尾追加，结束要关闭。文本与记录格式需约定字段、分隔、类型与换行。

def load_marks(path):
    marks = []
    with open(path, "r", encoding="utf-8") as source:
        for line in source:
            text = line.strip()
            if text:
                mark = int(text)
                if not 0 <= mark <= 100:
                    raise ValueError("Mark out of range")
                marks.append(mark)
    return marks


try:
    values = load_marks("marks.txt")
except FileNotFoundError:
    print("Marks file was not found")
except ValueError as error:
    print("Invalid mark data:", error)
else:
    print("Loaded", len(values), "marks")

with 保证正常或异常离开时关闭文件。Exception 是执行时出现的异常事件；try 包围可能失败的操作，except 针对类型处理；else 在未发生异常时运行；finally 执行必要清理。只捕获能恰当处理的错误，不用空的 except 掩盖缺陷。Validation 提前检查规则，exception handling 处理实际失败，二者可配合。

Serial、sequential、random 实践

  • Serial：追加记录后按存入顺序处理。
  • Sequential：按键排序保存，批处理或合并时维持顺序；插入可能需要重写文件。
  • Random/direct：由 record key、索引或 hash 得到记录地址，定位并读/写；需要固定记录长度或可靠位置索引。

官方伪代码可表达：

OPENFILE "students.dat" FOR RANDOM
SEEK "students.dat", Position
GETRECORD "students.dat", Student
SEEK "students.dat", Position
PUTRECORD "students.dat", Student
CLOSEFILE "students.dat"

Python 的 seek() 通常按字节偏移（文本流另有位置规则），不自动对应官方伪代码的“第几条记录”。固定长二进制记录可按 offset=index*record_size 寻址；变长 UTF-8 文本不能简单按字符数乘长度定位。Hash 冲突处理见第 13 章。
