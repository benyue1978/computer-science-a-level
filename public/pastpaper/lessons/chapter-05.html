05 系统软件 System Software

中文知识点提要 · Cambridge 9618 · 2027–2029 考纲

5.1 Operating Systems

练习本知识点 →

OS 管理硬件资源，为应用提供服务并向用户提供接口。

管理任务具体工作
Memory分配/释放内存，保护进程地址空间
Process创建/调度进程，分配 CPU 时间，处理中断
File目录、文件名、存取、权限与磁盘空间
Hardware/I/O驱动设备、缓冲、处理设备中断
Security用户认证、访问权限、审计与保护

Utility software 维护系统：formatter 建立文件系统；virus checker 检测/隔离恶意软件；disk analysis 报告空间使用；disk repair 检查并修复可修复的文件系统问题、标记坏块；compression 减小文件；backup 创建可恢复副本。Defragmenter 整理碎片减少 HDD 寻道，不能把它当作 SSD 的常规提速手段，也不保证修复物理损坏。

Program library 提供已编写的 routines，节省开发时间、复用经测试代码；仍需验证接口、版本兼容、许可与安全。DLL 在加载/运行时链接，共享库代码可减少重复占用、独立更新；缺失库或不兼容更新可能使程序失败。

5.2 Language Translators

练习本知识点 →

工具输入与执行方式优势/代价
Assembler汇编→机器码处理助记符、地址和标签，面向特定架构
Compiler对源代码进行翻译，生成目标代码/中间代码生成本机代码后通常运行快；修改后要重新翻译，目标有平台依赖
Interpreter在运行时分析并执行源代码或中间表示交互测试方便；通常有运行开销，运行环境必须可用

考试比较应区分“翻译时间”和“以后每次运行时间”。编译成功不保证没有逻辑/运行时错误；编译输出也不一定是独立可执行文件。解释执行不是要求每行必定生成可保存的机器码。

Java 是混合方式的例子：源代码编译为 bytecode，由 JVM 执行，可使用解释及 JIT。本章节只需理解部分编译、部分解释可兼顾可移植性与执行效率。

IDE 功能 → 帮助开发者的原因：

  • Context-sensitive prompt/auto-complete：提示合法标识符与参数，减少输入错误。
  • Dynamic syntax checking：编辑时标出语法问题。
  • Prettyprint：缩进/语法高亮改善可读性；expand/collapse 隐藏暂不关注的代码块。
  • Breakpoint：在指定位置暂停；single stepping：逐句运行。
  • Watch/report window：查看变量/表达式的值，定位状态何时偏离预期。

自测与易错点

1. 一个应用找不到 DLL，解释原因并说明动态链接的一个优势。

2. 为什么编译通过的程序仍可能除以零？为什么测试阶段适合使用断点？

3. 区分 OS、utility、application、translator；不要仅罗列名称而不解释任务。
