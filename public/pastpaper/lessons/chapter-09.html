09 算法设计与问题求解 Algorithm Design and Problem-solving

中文知识点提要 · Cambridge 9618 · 2027–2029 考纲

9.1 Computational Thinking Skills

练习本知识点 →

Abstraction 抽象：根据目的只保留必要细节，减少复杂度。例如公交路线模型保留站点、连接和车程，可省略车身颜色。必须解释为什么保留/忽略某信息。

Decomposition 分解：将大问题拆成输入、验证、处理、存储、输出等可独立理解和实现的模块，有助于分工、测试、复用。与 abstraction 不同：前者拆任务，后者筛细节。

9.2 Algorithms

练习本知识点 →

Algorithm 是解决问题的明确、有序步骤。设计时说明输入、输出、处理规则、结束条件及异常/边界情况。

Identifier table 记录变量名、类型和用途，例如 Total: INTEGER 累计总分；Count: INTEGER 有效输入数。变量名应表达用途。

三种基本结构：sequence 顺序；selection 根据条件选分支；iteration 重复处理。Structured English 用受限自然语言描述逻辑；pseudocode 用语言无关的结构；flowchart 使用开始/结束、输入输出、处理、判定等标准符号。

Stepwise refinement 逐步细化：先写“计算平均分”，再拆成初始化、循环读取/累计、检查数量、除法与输出，直到每步可以直接实现。

例：读取分数，−1 结束

DECLARE Mark, Count, Total : INTEGER
DECLARE Mean : REAL
Count ← 0
Total ← 0
INPUT Mark
WHILE Mark <> -1 DO
    IF Mark >= 0 AND Mark <= 100 THEN
        Total ← Total + Mark
        Count ← Count + 1
    ELSE
        OUTPUT "Invalid mark"
    ENDIF
    INPUT Mark
ENDWHILE
IF Count > 0 THEN
    Mean ← Total / Count
    OUTPUT Mean
ELSE
    OUTPUT "No valid marks"
ENDIF

关键：sentinel 不参与累计；每轮重新输入，避免死循环；Count=0 时不除零；非法输入不增加 Count。

条件、流程图与追踪

  • “不在 1–10”写为 X < 1 OR X > 10；不是 AND。
  • NOT (A AND B) 等价于 NOT A OR NOT B。
  • 从流程图转伪代码，先找判断和回边，判别前测/后测循环。
  • Dry run 使用 trace table 逐步记录变量、条件和输出。输入 80,120,60,-1 最终 Total=140、Count=2、Mean=70，并输出一次错误提示。
  • 不同算法比较时检查正确性、可读性、运算次数和所需存储；本章重点是将问题转成清晰步骤。

自测与易错点

1. 不运行程序，追踪第一项就是 −1 的情况，应输出 No valid marks。

2. 设计从 N 个可能全为负数的数中找最大值：使用第一项初始化，而非把最大值设为 0。

3. 把以上算法画成流程图，确保每个判定的两条出口、循环回边和结束路径明确。
